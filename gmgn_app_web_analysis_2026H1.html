结论 · 更支持「App 承接 Web 溢出」
  • 先 Web 后 App（16,054 人，46.0%）是先 App 后 Web（10,114 人，28.9%）的 1.6 倍——双端用户主要由 Web 起步；且该方向无论转向前还是转向后价值都全面更高（转向前人均 $46.3K vs $13.6K，转向后 $154.1K vs $86.7K）。
  • 方向间的价值差在转向前就已存在——Web 吸引的本来就是更重的用户；转向后人均总额的抬升主要来自统计时段变长（转向前中位仅 6~7 天），跨端更像高价值用户生命周期中的一站，而非价值跃迁的原因。
  • 以日均交易额中位数做公平对比，两个方向转向后均低于转向前（$180→$71、$96→$50），符合首期热度自然衰减——没有证据显示跨端本身提升单位时间交易强度。
  • 首次跨端间隔中位数 6~7 天；25.1% 同日双端成交（间隔中位约 2.7 小时）更像天然多端用户而非「被转化」，其转向前指标无解释意义。

附

口径存疑处与异常值处理

金额异常值（最重要）
1,585 笔 amount_usd ≥ $100 亿的订单全部集中在 chain='stable'（该链其余订单最大仅 ~$7K、中位数 $50，且 $1M~$1e8 区间为空），判定为稳定币金额未按 decimals 换算的单位错误。所有金额类指标中按 0 剔除；用户数、笔数保留。若按 ÷1e6 还原约 $53 亿，因无法验证换算系数未采用。另有 34,441 笔（0.038%）金额为空按 0 计；无负值与非数值脏数据。
source 口径覆盖
%_app/%_web 覆盖 90,830,311 笔；裸值 source='app'（3.8万笔）、'web'（2.4万笔）、空串（32.8万笔）及 openapi / bot / cooking 等约 106 万笔不在统计内，各端用户数被轻微低估（<0.1%）。另注意 SQL LIKE 的 _ 是单字符通配符，对当前 source 集合核对无误伤，但未来新增 xapp 类名称会被误纳入。
「全表首次成交」的定义
新用户判定取该 user_id 全表（不限时间窗、不限 source）中 state='30' AND kind='1' 的最早成交——经 openapi/bot 首次成交的也算老用户。
数据 3 的「首次」限于时间窗内
2026 年以前已有双端行为的老用户，其窗内「首次」并非真实首次，方向判定反映的是本时间窗内的行为顺序。「同日」按 Asia/Shanghai 自然日比较，同日内不再分先后。
数据 4 / 数据 5 的增补口径
数据 2、数据 3（转向前/转向后）、数据 4、数据 5 与数据 1 主表（月度行）及页头指标卡均为 2026-07-28 快照；仅数据 1 的分链/新老拆分仍为 07-26 快照，7 月相关绝对值略低于最新值，占比类指标不受影响。表为实时更新，同快照日不同批次仍可能有 <0.05% 的差异（如数据 2 双端 34,946 vs 数据 3 的 34,942）。留存口径：不要求连续留存、不区分回访端；目标月为 7 月的留存点受 7 月行情放量影响偏高（M+6 相对 M+5 出现翘尾）。日度「双端」= 同一自然日两端均有成交，口径严于月度。
其他
数据 1 各月用户数不可跨月加总（跨月活跃用户会重复）；数据 2 分位数是「每用户总交易额」的用户维度分布，不是单笔金额分布；7 月为不完整月（数据到 07-26），绝对值偏低但占比类指标可比；表为实时更新，不同查询批次的合计存在 <0.01% 的快照差异。
