结论
  • 双端占比全年稳定在 22.8% ~ 25.4%，1~6 月缓慢下行、7 月回升至 24.3%，没有出现双端融合加速的趋势。

结论 · 更支持「App 承接 Web 溢出」
  • 先 Web 后 App（15,854 人，46.0%）是先 App 后 Web（9,966 人，28.9%）的 1.6 倍——双端用户主要由 Web 起步。
  • Web→App 方向质量更高：转向后人均 $153.0K vs $86.6K，中位数 $5.8K vs $4.3K——是 Web 高价值用户在向 App 延伸，而非 App 向 Web 输送高价值用户。
  • 首次跨端间隔中位数 6~7 天；另有 25.1% 同日双端成交（间隔中位数约 2.7 小时），更像天然多端用户而非「被转化」，解读时应单列。
附

口径存疑处与异常值处理

金额异常值（最重要）
1,585 笔 amount_usd ≥ $100 亿的订单全部集中在 chain='stable'（该链其余订单最大仅 ~$7K、中位数 $50，且 $1M~$1e8 区间为空），判定为稳定币金额未按 decimals 换算的单位错误。所有金额类指标中按 0 剔除；用户数、笔数保留。若按 ÷1e6 还原约 $53 亿，因无法验证换算系数未采用。另有 34,441 笔（0.038%）金额为空按 0 计；无负值与非数值脏数据。
source 口径覆盖
%_app/%_web 覆盖 90,830,311 笔；裸值 source='app'（3.8万笔）、'web'（2.4万笔）、空串（32.8万笔）及 openapi / bot / cooking 等约 106 万笔不在统计内，各端用户数被轻微低估（<0.1%）。另注意 SQL LIKE 的 _ 是单字符通配符，对当前 source 集合核对无误伤，但未来新增 xapp 类名称会被误纳入。
「全表首次成交」的定义
新用户判定取该 user_id 全表（不限时间窗、不限 source）中 state='30' AND kind='1' 的最早成交——经 openapi/bot 首次成交的也算老用户。
数据 3 的「首次」限于时间窗内
2026 年以前已有双端行为的老用户，其窗内「首次」并非真实首次，方向判定反映的是本时间窗内的行为顺序。「同日」按 Asia/Shanghai 自然日比较，同日内不再分先后。
其他
数据 1 各月用户数不可跨月加总（跨月活跃用户会重复）；数据 2 分位数是「每用户总交易额」的用户维度分布，不是单笔金额分布；7 月为不完整月（数据到 07-26），绝对值偏低但占比类指标可比；表为实时更新，不同查询批次的合计存在 <0.01% 的快照差异。
