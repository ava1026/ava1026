一、原文精读

第 1 章 · 创业生命周期，2026 版本

没写过一行代码的人，今天也在出货生产级应用；"10 人独角兽"从草根传奇变成主动选择的路径。

2026 年 AI 已经能：写生产代码、做市场调研、综合竞品全景、起草投资人材料、自动化运营流程。

传统弧线被改写——验证→融资→招聘→构建→再融资→增长→再招聘→循环 这条路径背后"每一阶段都必须扩团队 / 换技能栈 / 再融一轮"的预期被 AI 抹掉了。本手册按 Idea / MVP / Launch / Scale 四个阶段重新映射创业旅程。

第 2 章 · 创始人的角色在变

过去靠"能做什么"定义创始人：技术型写代码，非技术型搞业务。2026 年，"会做的人"和"有好点子的人"之间的墙被融掉了。

创始人从执行者转为 agent 编排者（orchestrator of agents）——让专门化 AI 助手读文件、跑命令、执行代码、上网；自己负责"做什么 / 为什么"。

真正革命性的是：让有领域专长的非技术创始人被解放，会出现传统技术创始人 pipeline 从没关注过的问题被新人解决。

第 3 章 · Idea 阶段

目标
研究驱动的验证——在投入构建前凑齐"问题真实 + 方案对症"的证据。
退出标准
  1. 问题真实且具体（说得出谁、多频、多严重、目前如何应对）
  2. 方案对症（针对验证过程揭示出来的真问题）
  3. 信号足以让"做 MVP"是推理决定而非信仰行为
主要挑战
  • Mistaking building for validating：原型 ≠ 验证证据；对话本身才是。先前 42% 创业死于"做了没人要的东西"，AI 时代比例只会上升。
  • 过早扩张：构建几乎零成本时，执行很容易冲到验证前面。系统里的智能是你，要把"理解"保持在"构建"之前。
  • 失去客观性：让 AI 证明你的信念，它会找证据；解药是反着用——让 AI 给你的想法施压。结构化魔鬼代言人是全书每个阶段通用用法。

第 4 章 · MVP 阶段

目标
把已验证问题翻成真用户会用的可工作产品；快的同时不积累会复利的技术债；第一天起就投资持久上下文（如 CLAUDE.md）。
退出标准
可识别用户群体的 R³——Retention / Revenue / Referral 都有真实证据，且模式在多个迭代周期持续。
主要挑战
  • Agentic 技术债：与普通技术债不同，会复利。没有写下的规格和约束，每次会话都重新推导基础决策、互相漂移，最后代码"没有连贯的心智模型"。
  • 假性 PMF：早期势能由短暂力量驱动（朋友、组合公司、HN 头条），不能预测 6 周或 12 周后。
  • 零摩擦的范围蔓延：每个新功能"显得合理"。解药：动工前先写下范围定义。把决策从"我们要做这个吗"挪到"是否有临界质量的用户告诉我们没有这个就无法获得价值"。
  • 由经验不足造成的安全漏洞：agentic coding 产出"能跑"的代码不是"安全"的代码；漏洞在被利用前是隐形的。
PMF 试金石
  • Sean Ellis 测试：>40% 用户回答"非常失望" = 有意义的 PMF 指标
  • 努力测试：留存从靠创始人英雄式干预（推）变成产品自己工作（拉）
  • 没有单一数据点能确证 PMF——必须是多个迭代周期里都成立的模式

第 5 章 · Launch 阶段

MVP 是证明产品该存在；Launch 是证明业务该长。
目标
把早期势能变成可重复增长引擎；硬化基础设施；围绕产品造一家公司。目标不是让你离开公司，而是建运营系统把你的注意力解放出来。
退出标准（全过）
  1. 增长可重复、渠道驱动——CAC / LTV / 回收周期能说清
  2. 产品能扛真实生产负载（不止你测过的条件）
  3. 运营无创始人瓶颈
主要挑战
  • 技术债到期：MVP 时为速度欠债合理；Launch 时开始生息。
  • 创始人成瓶颈：本应 1 小时的决策要一周；支持请求堆积；任务只在你记得时才发生。
  • 安全合规不能再推迟：把发现项视为必须修复而不是建议。
  • 没准备好就扩张：新市场让你失去对自己数据的解读能力。
结构性关键：Claude Code 造产品 + Cowork 围绕产品造公司 + Claude 把产品与组织知识可操作化——三者互为输入、有机复利，这就是超精益创业模式在结构上能成立的原因。

第 6 章 · Scale 阶段

创始人重心从构建者变成对外的公众型高管（分析师 briefing、IPO 路演加入日程），同时维持"以 AI 为核心的精益结构优势"。

目标
用户从千级到百万、市场从一个到多个；建一条"通过累积深度（accumulated depth）打造的护城河"——产品里凝固的专业知识 + 与用户依赖工具的集成深度 + 自有系统数据和工作流。
退出标准
不再是某个里程碑，而是阈值事件：公司在创始人逐步不再亲自管日常的情况下可持续。能回答"如果一个资金充裕的在位者今天复制你的产品，用户会留下吗？" 落到三种形态之一：
  • 不需要外部资本的可持续盈利
  • IPO 就绪
  • 被收购
主要挑战
  • 运营层交接：交得太多太快 → 关键决策失去创始人独有上下文；握得太久 → 你成瓶颈。把"只活在脑子里"的工作流知识编码成可文档化、可审计、可移交的系统。
  • 技术运营要规模化：客户要的不只是产品，而是"组织能做可靠基础设施伙伴"。
  • 组织职能要规模化：招聘 / 薪酬 / 会计 / 法务等迟早要建。
  • GTM 函数构建：有机增长有天花板，多数 Scale 创始人在撞墙前从没真正建过 GTM。

第 7 章 · 同样的工作，新的规则

  • 验证：几个月 → 几个下午
  • 原型：不再需要带正确技术栈的联合创始人，只需清晰问题 + 几次专注 coding agent 会话
  • 发布就绪：从临阵磨枪 → 一条持续工作流
  • 规模：早期招聘里被迫做救火的运营负担越来越多可交给 AI
瓶颈不再是"你能造什么"，而是"你选择造什么"。

四、Chat / Cowork / Code 决策卡

一句话定义

Claude Chat

一次性、对话式、不离开当前 App。对话。

立刻使用
  • 在密集投资人备忘录里抓一句要点
  • 开董事会前对一个数据做 sanity check
  • 一长串 Slack 讨论里提炼上下文
  • 给一段文案做改写、起标题
  • 让 AI 反驳你的某个想法

Claude Cowork

多源拉取、产出成品、可定时、可连工具。工作会话。

立刻使用
  • 一文件夹访谈转录 → 主题发现文档
  • 融资前十几家供应商拼竞品全景
  • 每周从已接入工具拉指标 → KPI brief
  • 自动外联 + 排期 + 跟进 + 跟踪
  • bug 分诊路由、文档随产品更新、续约提醒

Claude Code

直接动代码库，写、测、提交、合。工程环境。

立刻使用
  • 跨多文件改动并跑测试
  • Plan Mode 先给方案再执行
  • 架构审计 / 安全审 / 重构
  • 原型迁生产
  • 建集成、API、webhook、SDK、demo 环境
  • 把脑子里的边角案例固化为场景测试

不该用 / 易混淆的边界

场景❌ 别用✅ 应该用原因
用户调研综合（10+ 份访谈）ChatCoworkChat 没文件夹访问 / 没记忆持久度
修改业务代码 + 跑测试CoworkCodeCowork 没 diff / git / 沙盒
替代有资质的合规审Code / Cowork人类专家原文明示：AI 扫描是辅助
MVP 安全审涉真数据Code 一遍过Code + 人类复核触认证 / 密钥 / 数据必须人审
用户反馈细腻语义解读Cowork 全自动自己先读，再 AI 找漏点保留人在采集环里
早期假设求证（想被支持时）"Claude 帮我证一下""Claude 帮我反驳"反着用 = 反 AI 确认偏误

同时用三者的"复利模式"

Launch / Scale 阶段的关键。三者互为输入。

Claude Code 造产品 ──→ 产出：代码、审计结果、安全发现 │ ▼ Claude 综合 / 决策 ──→ 产出：优先级、Sprint 序列、控制矩阵 │ ▼ Claude Cowork 跑运营 ──→ 产出：工单、文档更新、报告节奏 │ └──→ 反馈进入 Claude Code 的下一轮工作
原文原话："This is what makes the ultra-lean startup model structurally possible."
三者互为输入、有机复利，是超精益创业能成立的结构原因。
