### 第 1 章 创业生命周期，2026 版本

- 没写过一行代码的人也在出货生产级应用；"10 人独角兽"从草根传奇变成主动选择的路径。
- 2026 年 AI 可以做：写生产代码、做市场调研、综合竞品全景、起草投资人材料、自动化运营流程。
- 传统弧线 `验证→融资→招聘→构建→再融资→增长→再招聘→循环` 被改写：AI **抹去了"每一阶段都必须扩团队 / 换技能栈 / 再融一轮"的预期**。
- 本手册按 **Idea / MVP / Launch / Scale** 重新映射创业旅程。

### 第 2 章 创始人角色在变

- "会做的人"和"有好点子的人"之间的墙被融掉。
- 创始人从执行者转为 **agent 编排者（orchestrator of agents）**。
- 革命性意义：让有领域专长的非技术创始人被解放。

#### 精益初创公司 AI 的三类能力

| 能力 | 类比 | 用法 |
|---|---|---|
| 对话式智能 + 研究 | "全领域随叫随到的专家" | 深度研究 / 文档起草 / 战略陪练（魔鬼代言人、事前剖析、情景规划） |
| Agentic coding | "永远在线、永不被堵的工程师" | 自然语言描述要建什么；AI 生成 / 测试 / 调试 / 重构产品级代码 |
| 工作流自动化 | "随时待命的运营团队" | CRM 同步 / 周报生成 / 文档随产品更新；Cowork 接 PM 工具 / 通讯栈 / 数据源 |

#### Claude 三个产品面（全书反复引用）

| 任务 | 用 | 为什么 |
|---|---|---|
| 一个问题、改写、快速头脑风暴 | **Chat** | 对话式、无需设置、不离开当前 App |
| 调研、分析、用文件和系统拼出成品文档 | **Claude Cowork** | 有文件夹访问、connectors、skills、可定时运行 |
| 写、测试、发布软件 | **Claude Code** | 有代码库访问、diffs、git、本地/IDE/沙盒云环境 |

### 第 3 章 Idea 阶段

**目标**：研究驱动的验证——在投入构建前凑齐"问题真实存在 + 方案能解"的证据。

**退出标准（三条全过）**
1. 问题真实且具体（能说出谁经历、多频繁、多严重、目前如何应对）
2. 方案对症（针对验证过程**揭示出来的真问题**，不是最初假设的）
3. 信号足够支撑动工（不需要确定性，但要让"做 MVP"是推理决定而非信仰）

**挑战**
- **Mistaking building for validating**：原型 ≠ 验证证据；对话本身才是。先前 42% 创业死于"做了没人要的东西"，AI 时代比例只会上升。
- **过早扩张**：构建几乎零成本时，执行很容易冲到验证前面。**系统里的智能是你**——把"理解"保持在"构建"之前。
- **失去客观性**：让 AI 证明你的信念，它会找证据；解药是**反着用**——让 AI 给你的想法施压。**结构化魔鬼代言人是全书每个阶段的通用用法**。

**Idea 阶段 Claude 用法**
1. 定义并压力测试问题假设（让 Claude 反驳、找反证）
2. 竞品全景：按层（直接 / 间接 / 潜在收购方 / 邻近）映射，并让 Claude 论证为何对你构成真威胁；用 Cowork 综合竞品评测找未被解决的最痛点
3. 趋势分析：找 3 个外部趋势（监管 / 技术 / 人口）→ 顺/逆风
4. 客户访谈：精确目标画像；问"过去时的具体行为"而非"未来时的通用意愿"；Claude 审引导性问题
5. 访谈后复盘：每 5 次让 Cowork 出两份证据清单（支持 / 反对）
6. 触达自动化：Cowork 建名单 + 起草 + 接 Gmail/Calendar + 自动跟进
7. 方案概念审：让 Claude 找 3 个最依赖的假设
8. 最后才用 Claude Code 建单一核心交互原型，放到 5 个目标用户面前

### 第 4 章 MVP 阶段

**目标**
- 把已验证问题翻成真用户会用的可工作产品
- **快**的同时不积累**会复利**的技术债
- **第一天起就投资持久上下文**（如 `CLAUDE.md`）

**退出标准**：真正的 PMF 证据——可识别用户群体的 **R³**：Retention / Revenue / Referral 都有真实证据，且模式在多个迭代周期持续。

**挑战**
- **Agentic 技术债**：与普通技术债不同，会**复利**。没有写下的规格和约束，每次会话都重新推导基础决策，互相漂移；最后代码"没有连贯的心智模型"。
- **假性 PMF**：早期势能由短暂力量驱动（朋友、投资人组合公司、HN 头条），不能预测 6 周或 12 周后。
- **零摩擦的范围蔓延**：每个新功能"显得合理"；解药是**动工前先写下范围定义**。决策从"我们要做这个吗"挪到"是否有临界质量的用户告诉我们没有这个就无法获得价值"。
- **由经验不足造成的安全漏洞**：agentic coding 产出的是"能跑"的代码不是"安全"的代码；漏洞在被利用前是隐形的。

**PMF Litmus Tests**
- **Sean Ellis 测试**：>40% 用户回答"非常失望" = 有意义的 PMF 指标
- **努力测试**：留存从靠创始人英雄式干预（"推"）变成产品自己工作（"拉"）
- **没有单一数据点能确证 PMF**——必须是**多个迭代周期里都成立的模式**

**MVP 阶段 Claude 用法**
1. 动工前用 Chat 写架构原则，存为 **`CLAUDE.md`**（项目级"持久记忆"，Agent SDK 自动读取）
2. 写 MVP **范围文档**（做什么 / 不做什么 / 修订标准）
3. 用 Claude Code 建，每次会话开头读范围 + `CLAUDE.md`，结束 5 分钟更新日志（**最便宜的架构漂移保险**）
4. **用户接触前**做安全审：认证 / 数据暴露 / 输入校验 / 漏洞依赖；触认证/密钥/数据的发现必须**人工复核**。**Claude Code Security**（撰写时为有限 beta）做扫描 + 建议补丁
5. **发布前**建度量框架：留存基线 / 激活 / Day 7 / Day 30 + 定义假阳性
6. Cowork 跑反馈闭环；**自己先读综合报告**，再让 Claude 找漏点
7. 数据不动 → pivot 不是失败，是系统在工作；三问诊断（细分群体？定位 vs 产品？要什么为真？）

### 第 5 章 Launch 阶段

**主题**：MVP 是证明产品该存在；**Launch 是证明业务该长**。

**目标**：把早期势能变成可重复增长引擎；硬化基础设施；**围绕产品造一家公司**。目标不是让你离开公司，而是建运营系统把你的注意力解放出来。

**退出标准（三条全过）**
1. 增长**可重复、渠道驱动**——CAC / LTV / 回收周期能说清
2. 产品能扛**真实**生产负载
3. 运营**无创始人瓶颈**

**挑战**
- **技术债到期**：MVP 时为速度欠债合理；Launch 时开始**生息**
- **创始人成瓶颈**：本应 1 小时的决策要一周；支持请求堆积；任务只在你记得时才发生
- **安全合规不能再推迟**：把发现项视为**必须修复**而不是建议
- **没准备好就扩张**：新市场让你**失去对自己数据的解读能力**

**结构性关键**：Claude Code 造产品 + Cowork 围绕产品造公司 + Claude 把产品和组织知识可操作化——三者**互为输入、有机复利**，**这就是超精益创业模式在结构上能成立的原因**。

**Launch 阶段 Claude 用法**
1. Claude Code 跑全架构审计 → Claude 排序成多 Sprint 修复计划；把"只在你脑子里"的架构决策补进 `CLAUDE.md`
2. Cowork 做运营审计 → 分类：全自动 / 需人但非你 / 必须创始人；为自动化候选设计工作流逻辑
3. **安全合规做成持续工作流**：Code 跑面向 SOC 2 / GDPR / HIPAA 的代码级审；Claude 输出修复序列 + 企业采购合规文档清单。**AI 扫描是辅助，不能替代有资质的合规审查**
4. 设计轻量 PM 操作系统：Sprint 节奏 / 最简 spec 模板 / bug 分诊决策树 / 周指标 brief；Cowork 跑

### 第 6 章 Scale 阶段

**主题**：创始人重心从构建者变成**对外的公众型高管**（分析师 briefing、IPO 路演加入日程），同时维持"以 AI 为核心的精益结构优势"。

**目标**
- 用户从千级到百万级、市场从一个到多个
- **建一条"通过累积深度（accumulated depth）打造的护城河"**：产品里凝固的专业知识 + 与用户依赖工具的集成深度 + 自有系统数据和工作流
- 扛外部审视：公开市场投资人 / 分析师 / 监管 / 企业采购 / 收购方

**退出标准（阈值事件，非里程碑）**：公司在创始人**逐步不再亲自管日常**的情况下可持续；并能回答"**如果一个资金充裕的在位者今天复制你的产品，用户会留下吗？**"。落到三种形态之一：
- 不需要外部资本的可持续盈利
- IPO 就绪
- 被收购

**挑战**
- **运营层交接**：交得太多太快 → 关键决策失去创始人独有上下文；握得太久 → 你成瓶颈。核心难题是**把只活在你脑子里的工作流知识编码成可文档化、可审计、可移交的系统**
- **技术运营规模化**：客户要的不只是产品，要"组织能做可靠基础设施伙伴"
- **组织职能规模化**：招聘 / 薪酬 / 会计 / 法务
- **GTM 函数构建**：有机增长有天花板；多数 Scale 创始人在撞墙前从没真正建过 GTM

**Scale 阶段 Claude 用法**
1. **Claude 列只有你应做的事**（产品叙事 / 董事会 / 企业大单 / 创始人对创始人），其他都是交付候选
2. **瓶颈地图**："你一周不在每条工作流会怎样" → 会停的就是你还在亲自托底的
3. **企业级技术运营**：Claude 起草产品文档 / 支持 playbook / SLA；Code 按企业标准硬化代码并建日志 / 监控 / 事故响应 / 可观测层；Cowork 跑工单 / 升级 / 文档更新 / 续约
4. **3 个理想企业客户差距分析**
5. **真 GTM 函数**：Claude 搭分层 / 信息架构 / 销售 playbook / 投资人指标叙事；Cowork 跑战术（内容 / 外呼 / 分析师 / CRM）；Code 建交互式 demo / 集成文档 / 沙盒 / API 参考——**"一个好建出来的 demo 环境能在你开董事会时帮你成交"**
6. **领域专长 → AI 上下文**：项目 + 记忆把行业黑话 / 监管陷阱 / 边角案例 externalize；**Skills** 把反复工作流固化成可复用例程。几个月后是**自有知识底层**
7. **找通才竞品一定会做错的边角案例 → Code 写场景测试 → 测试集就是护城河地图**
8. **数据飞轮 → 护城河叙事**：3 个最高信号行为模式 + 反馈环设计 + 一页"为什么资源充裕的竞品 2 年内复制不了"
9. **工作流锁定**：数据网络效应让产品难复制，工作流锁定让产品**难离开**。前 10 客户集成审计找跨群规律 → 决定深化方向。Code 建 API/webhook/SDK——客户在你产品上**建**就是最深的锁定

### 第 7 章 同样的工作，新的规则

- 创始人工作没变：找真问题、做能解、扩成有分量的公司
- 变的是路径：AI 把季度压缩成几周
- 验证：几个月 → 几个下午
- 原型：不再需要带正确技术栈的联合创始人，**只需要清晰问题 + 几次专注 coding agent 会话**
- 发布就绪：从临阵磨枪 → 一条持续工作流
- 规模：早期招聘里被迫做救火的运营负担越来越多可交给 AI
- **结论**：**瓶颈不再是"你能造什么"，而是"你选择造什么"**

## 二、四阶段可执行 Checklist

### Idea 阶段

**进入条件**：你有一个挥之不去的问题观察。

**Do**
- [ ] 把"问题陈述"打磨到具体可测（**谁 / 多频 / 多严重 / 现状**）
- [ ] 让 Claude **反驳**你的想法、找反证
- [ ] 让 Claude **按层映射**竞品（直接 / 间接 / 潜在收购方 / 邻近）并为每层写"为何是真威胁"
- [ ] 用 Cowork 综合竞品在各渠道评价 → 找出**未被解决的最痛点**
- [ ] 搭 TAM / SAM / SOM 并压测假设
- [ ] 找 **3 个外部趋势**（监管 / 技术 / 人口）→ 标注顺风/逆风
- [ ] 定义客户画像（职位、公司类型、团队结构、资历）+ 聚集社区
- [ ] 手写访谈题 → Claude 审"引导性 / 未来式 / 社会期许式" → 加追问
- [ ] Cowork 跑触达：名单 + 个性化邮件 + Gmail/Calendar + 节奏跟进
- [ ] 每 5 访谈让 Cowork 出两份清单（支持 / 反对），不对称时让 Claude 判读
- [ ] 让 Claude 找方案概念**最依赖的 3 个假设**
- [ ] Claude Code 只建**单一核心交互**，放到 5 个目标用户面前

**产出物**：可测试假设句 / 竞品分层图 / TAM-SAM-SOM 模型 / 客户画像 + 反馈数据库 / 单一核心交互原型

**退出标准（三条全过）**
- [ ] 问题真实且具体
- [ ] 方案对症（不是最初假设的那个）
- [ ] 信号足以让"做 MVP"是推理决定而非信仰

**反模式**：把原型当验证证据 / 让 AI 帮你证明已有信念 / 问"未来时通用"而非"过去时具体"

### MVP 阶段

**进入条件**：Idea 三条退出标准全过。

**Do**
- [ ] 在打开 Claude Code 之前，先和 Claude 写下架构原则 / 禁用依赖 / 接受取舍
- [ ] 把上一步输出存为 **`CLAUDE.md`**
- [ ] 写 MVP **范围文档**（做什么 / 刻意不做 / 修订标准）
- [ ] 建会话模板（架构上下文 + 本次任务 + 约束）
- [ ] 每次会话结束写 5 分钟日志（做了什么 / 决策 / 引入假设）
- [ ] **上线前**安全清单：认证与会话、API 数据暴露、输入校验、已知漏洞依赖
- [ ] 在**第一个用户出现前**定义度量：留存、激活、Day 7 / Day 30、假阳性
- [ ] Cowork 跑反馈闭环（外联、约会、bug/feature 收件、周综合）
- [ ] 周综合**先自己读**，再让 Claude 找漏点
- [ ] PMF litmus：Sean Ellis（>40% "非常失望"）+ 努力测试（产品从"推"变"拉"）
- [ ] 3+ 个迭代周期无 PMF 移动 → Claude 三问诊断

**产出物**：`CLAUDE.md` / 范围文档 + 会话模板 / 度量框架（含假阳性）/ 安全审报告 / 周反馈综合

**退出标准**
- [ ] 可识别用户群体的 R³：Retention / Revenue / Referral 都有真实证据
- [ ] 模式在多个迭代周期持续

**反模式**：零摩擦范围蔓延 / 把短暂势能当 PMF / 上线后才追指标 / 无 spec 无 `CLAUDE.md` 让 AI 自由发挥

### Launch 阶段

**进入条件**：MVP 阶段 PMF 证据成立。

**Do**
- [ ] Claude Code 跑**全架构审计**：结构弱点 / 测试覆盖缺口 / 重构候选（优先级化）
- [ ] 把 MVP 阶段"只在你脑子里"的架构决策**补写进 `CLAUDE.md`**
- [ ] Claude 把修复任务**编排成 Sprint 序列**（必修 / 可缓 / 持续债）
- [ ] Cowork 做运营审计：列每个常规任务 / 决策 / 只因你记得才发生的工作流
- [ ] Cowork 分类：**全自动 / 需人但非你 / 必须创始人**
- [ ] 为自动化候选设计工作流逻辑（触发 / 规则 / 输出 / 去向）
- [ ] Claude Code 跑面向目标市场框架（SOC 2 / GDPR / HIPAA）的代码级安全审
- [ ] Claude 输出（a）优先级修复序列（b）企业合规审所需文档/控制清单
- [ ] 合规做成**开发周期里持续工作流**，不是一次性项目
- [ ] Claude 设计轻量 PM 操作系统：Sprint 节奏 / 最简 spec 模板 / bug 分诊决策树 / 周指标 brief

## 四、Chat / Cowork / Code 决策卡片

### 一句话定义

| 工具 | 一句话 |
|---|---|
| **Claude Chat** | 一次性、对话式、不离开当前 App，**对话** |
| **Claude Cowork** | 多源拉取、产出成品、可定时、可连工具，**工作会话** |
| **Claude Code** | 直接动你的代码库，**写、测、提交、合**，**工程环境** |

### 决策树

```
                ┌────────────────────────────────────────┐
                │ 我要做的是什么？                       │
                └────────────────────────────────────────┘
                              │
        ┌─────────────────────┼──────────────────────┐
        ▼                     ▼                      ▼
 ┌────────────┐        ┌──────────────┐        ┌────────────┐
 │ 快问 / 重写 │        │ 调研 / 综合  │        │ 代码 / 测试 │
 │ 简单脑暴   │        │ 文档 / 成品  │        │ 发布 / 代码 │
 └─────┬──────┘        └──────┬───────┘        └─────┬──────┘
       │                      │                      │
       ▼                      ▼                      ▼
   Claude Chat           Claude Cowork           Claude Code
```

### 触发器（看到这些 → 立刻用对应工具）

**→ 用 Chat 当**
- 在密集投资人备忘录里抓一句要点
- 开董事会前对一个数据做 sanity check
- 一长串 Slack 讨论里提炼上下文
- 给一段文案做改写、起标题
- 让 AI 反驳你的某个想法（任何阶段的"魔鬼代言人"）

**→ 用 Cowork 当**
- 把一文件夹客户访谈转录整理成下次产品评审的主题发现文档
- 上融资前把十几家供应商网站拼成竞品全景
- 每周一早晨从已接入工具里拉指标 → 写一份 KPI brief 进共享文件夹
- 自动跑外联 + 排期 + 跟进 + 跟踪表
- bug 分诊路由、文档随产品变化自动更新、续约提醒

**→ 用 Code 当**
- 跨多个文件改动并跑测试
- 用 Plan Mode 让它先给方案再执行
- 架构审计 / 安全审 / 重构
- 从原型迁到生产
- 建集成、API、webhook、SDK、demo 环境、沙盒租户、API 参考
- 把脑子里的边角案例固化为场景测试

### 不该用 / 易混淆的边界

| 场景 | ❌ 别用 | ✅ 应该用 | 原因 |
|---|---|---|---|
| 用户调研综合（10+ 份访谈） | Chat | Cowork | Chat 没文件夹访问 / 没记忆持久度 |
| 修改业务代码 + 跑测试 | Cowork | Code | Cowork 没 diff / git / 沙盒 |
| 替代有资质的合规审 | Code / Cowork | 人类专家 | 原文明示：AI 扫描是辅助 |
| MVP 安全审 carrying 实数据 | Code 一遍过 | Code + 人类复核 | 触认证 / 密钥 / 数据必须人审 |
| 用户反馈细腻语义解读 | Cowork 全自动 | 自己先读，再让 AI 找漏点 | 保留人在采集环里 |
| 早期假设求证（很想被支持时） | "Claude 帮我证一下" | "Claude 帮我反驳" | 反着用同一工具 = 反 AI 确认偏误 |

### 同时用三者的"复利模式"（Launch / Scale 阶段的关键）

```
   Claude Code 造产品 ──→ 产出: 代码、审计结果、安全发现
                                       │
                                       ▼
   Claude 综合 / 决策 ──→ 产出: 优先级、Sprint 序列、控制矩阵
                                       │
                                       ▼
   Claude Cowork 跑运营 ──→ 产出: 工单、文档更新、报告节奏
                                       │
                                       └──→ 反馈进入 Claude Code 的下轮工作
```

> 原文原话：*"This is what makes the ultra-lean startup model structurally possible."*
> 三者**互为输入、有机复利**，是超精益创业能成立的结构原因。
